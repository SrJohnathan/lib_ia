# lib_ia

`lib_ia` is a native AI bridge library built on top of `llama.cpp` and `whisper.cpp`.

It exposes:

- text generation
- chat completion
- reasoning/thinking support
- multimodal helpers for image, audio, and video-capable models
- speech-to-text bindings

The project is organized so the C++ side builds a shared library and the Rust side consumes it through FFI.

## What this repository contains

- `src/` - native C++ implementation of the exported API
- `client-rust/` - Rust workspace with bindings and example clients
- `vendor/` - third-party dependencies and model/tooling sources
- `CMakeLists.txt` - top-level C++ build

## Main components

### Native library

The C++ library is built as `liblib_ia.so` on Linux.

It is responsible for:

- wrapping `llama.cpp` features
- wrapping `whisper.cpp` features
- exposing a stable C ABI for Rust and other clients

Important native files:

- `src/library.cpp`
- `src/integration.cpp`
- `src/runtime.cpp`
- `src/sst.cpp`
- `src/integration.h`

### Rust bindings

The Rust crate lives in:

- `client-rust/lib-rust`

This crate:

- exposes safe Rust traits
- binds to the C ABI
- can link against an existing `lib_ia` build
- can also build the C++ side automatically when needed

### Example clients

Examples are in:

- `client-rust/inference`
- `client-rust/sst-inference`

They are useful to test normal inference and speech-to-text behavior.

## Folder structure

### `src/`

Native C++ source code.

- `library.cpp` - top-level exported API
- `integration.cpp` - chat/inference bindings
- `runtime.cpp` - model runtime and multimodal handling
- `sst.cpp` - speech-to-text FFI
- `integration.h` - exported C interface

### `vendor/`

External code and model dependencies.

This repository currently uses:

- `vendor/llama.cpp`
- `vendor/whisper.cpp`
- `vendor/test-inferencia`

These are large third-party trees and should be treated as vendored dependencies or submodules depending on how you manage the repository.

### `client-rust/`

Rust workspace:

- `inference` - text/chat example
- `sst-inference` - microphone speech-to-text example
- `lib-rust` - FFI crate

## External dependencies

To build the project you generally need:

- CMake
- a C++20 compiler
- Rust toolchain
- Vulkan development libraries and headers
- standard Linux build tools

On Linux, the native build is CPU + Vulkan only.
CUDA is not used.

The repository is based on:

- `llama.cpp`
- `whisper.cpp`

Both are built from the `vendor/` tree.

## Build the native library

From the repository root:

```bash
cmake -B build -S . -DGGML_CUDA=OFF -DGGML_VULKAN=ON
cmake --build build -j 2 --target lib_ia
```

This produces the shared library in the CMake build tree.

## Use from Rust

The recommended usage is as a local dependency, not from crates.io.

In your Rust project:

```toml
[dependencies]
lib-rust = { path = "/path/to/lib_ia/client-rust/lib-rust" }
```

The `lib-rust` crate can:

- link to an already built `lib_ia`
- or build the C++ side automatically if no prebuilt library is found

Useful environment variables:

- `LIBIA_BUILD_DIR` - path to a directory that already contains `liblib_ia.so`
- `LIBIA_SOURCE_DIR` - path to the `lib_ia` repository root
- `LIBIA_SKIP_CPP_BUILD` - force link-only mode

## SST usage model

The speech-to-text API is designed around two phases:

1. `start()` - prepare/reset the engine and open a capture session
2. `end()` - close the session and return the final text

The lower-level audio API also supports:

- `push_audio(..., finalize = false)` for ongoing capture
- `push_audio(..., finalize = true)` or `flush()` to finish and transcribe

The VAD path exists as a secondary mode, but the normal flow is session-based capture.

## Clone workflow

If you keep `vendor/` as submodules, clone with:

```bash
git clone --recurse-submodules <repo-url>
```

If you already cloned the repository:

```bash
git submodule update --init --recursive
```

## Notes

- This project is intended for local development and Git-based consumption.
- The Rust crate is designed to be used via `path = ".../lib-rust"`.
- The native `.so` is generated by the C++ build and consumed by the Rust crate.
